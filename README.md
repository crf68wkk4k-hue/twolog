# 투로그 · TwoLog

둘이 함께 쌓는 캘린더 · 노트 · 사진첩. 순수 HTML/CSS/JS 로 만든 설치형 웹앱(PWA)입니다.
빌드 도구도, 프레임워크도 없습니다. 폴더를 웹에 올리면 그대로 앱이 됩니다.

- **지금 바로** — 이 기기에서 혼자 쓰는 **로컬 모드**로도 완전히 동작합니다(인터넷·가입 필요 없음, 기록은 기기에 저장).
- **두 대 동기화** — `sync.js` 의 `CONFIG` 두 칸에 Supabase 주소/키를 넣으면 **실시간 동기화 모드**로 바뀝니다(무료 플랜으로 충분).
- **v25 부터**는 소영·준영의 프로젝트(`qvhupdivtfzhzymovtyy`)가 `CONFIG` 에 들어 있어 **배포 주소는 동기화 모드가 기본**입니다(로그인 화면 → 이메일 계정).
  기기에만 저장하는 예전 방식으로 열어 보려면 주소 뒤에 `?sync=local` 을 붙입니다(테스트도 이 통로를 씁니다).
- **v26 부터**는 폰에만 남아 있던 예전 기록(localStorage + IndexedDB)을 **처음 로그인할 때 한 번 자동으로 새 커플 공간으로 이어 옵니다**.
  이미 옮긴 기기는 다시 옮기지 않고(플래그 `twolog.migrated.<coupleId>`), 원본은 폰에 그대로 남깁니다.
  원격에 이미 기록이 있으면 자동으로는 건드리지 않고 **My 탭 → 「폰에 있던 예전 기록 가져오기」** 로 겹치지 않게 더할 수 있어요.
  같은 버전에서 **프로필 사진도 사람별로 동기화**됩니다(내 사진은 내가, 상대 사진은 상대 폰에서).
- **v28 부터**는 캘린더를 열 때 **늘 오늘이 속한 달**로 시작합니다(다른 달을 보다 다른 탭에 갔다 오거나 앱을 다시 켜면 이번 달).
  일정 시트에서는 **시간 설정을 없애고 날짜 위·요일(화요일) 아래**로 크게 보여 주며, 달력 아래 상세 일정을 **누르면 그 일정을 고칠 수 있습니다**.
  한 날 일정이 3개를 넘으면 달력 칸에 **`+1`** 로 알려 주고, 노트 알약 탭 줄 오른쪽의 **동그란 `+`** 로 새 카테고리 탭을 바로 만들 수 있어요(그 탭과 항목도 상대 폰에 함께 동기화).
- **v29 부터**는 노트 맨 윗줄 오른쪽의 **네모 설정 버튼을 없애고 동그란 `+`(새 카테고리 탭 추가)** 를 그 자리에 두었습니다.
  알약 탭(`메모`·`버킷리스트`·`영화·먹방`)은 높이 44 → 40px, 글씨 15.5 → 14px 로 조금 줄였고, 알약 탭 아래 칩 줄에 있던 `+` 는 없앴어요.
  **탭 이름 바꾸기(노트 설정)** 는 「📖 노트」 제목을 **꾹 누르면** 열립니다(화면에 버튼이 늘지 않게).
- **v30 부터**는 사진첩의 **폴라로이드를 더 작게** 했습니다. 하루 3개·3열·살짝 기울이는 구성은 그대로 두고,
  사진 한 칸을 118.7 → 93.3px(카드 130.7 → 103.3px·높이 142.7 → 113.3px)로 줄이고 카드끼리 겹치던 것을
  사이를 띄워(간격 14px) 한 화면에 더 아담하게 담았어요. 흰 프레임은 위·옆 5px, 아래 턱 15px, 캡션 9px 입니다.
- **v31 부터**는 일정에 고른 **색이 저장·동기화·새로고침 뒤에도 그대로** 남습니다.
  고치기 전에는 고른 색(`e.color`)이 `events` 행으로 올라가지 않아서, 확인을 누르거나 앱을 다시 열면 담당자 기본색으로 돌아갔어요.
  스키마는 그대로 두고 `events.memo`(text) 한 칸에 `{"end":"YYYY-MM-DD","color":"#RRGGBB"}` 로 담습니다(여러 날 종료일 + 고른 색).
  v30 이전에 올라간 `memo = "YYYY-MM-DD"`(종료일만) 행과 빈 `memo` 도 그대로 읽습니다.
  같은 버전에서 **노트 카드 시트 안의 항목 `×`** 를 누르면 시트가 닫히지 않고 그 자리에서 항목만 지워집니다(수정 시트의 「삭제」는 예전처럼 닫힘).
- **v40 부터**는 노트의 **「투두리스트」 속지가 2열 카드 묶음 + `+ 새 리스트`** 화면입니다.
  카테고리를 투두리스트로 만들면(예전에 항목만 있던 카테고리도) **카테고리 이름의 첫 카드** 안에 항목이 그대로 이어지고,
  `+ 새 리스트`로 카드를 더 만들고 카드를 눌러 제목·항목(Add·엔터)·체크·삭제를 해요. 카드 묶음은 `settings` 의 `groups` 에
  `list:<id>` 로 함께 올라가 두 폰이 같은 카드를 봅니다. **기본 카테고리의 「투두리스트」 선택지는 「카드」로 정리**했어요(저장돼 있던 값은 카드 화면으로).
  `+` 시트의 **속지 레이아웃은 목록 맨 아래가 아니라 카테고리 줄을 누르면 그 줄 «바로 아래»로 펼쳐지는 아코디언**입니다
  (같은 줄을 한 번 더 누르면 접히고, `추가`로 붙인 줄은 바로 펼쳐지며, `≡` 드래그를 시작하면 접혀요).
  **「줄글 메모」는 「모눈 메모」** 가 되어 모눈종이 바탕 위에 **둥근 흰 일기 카드**(맨 위 왼쪽에 `2026.11.21 토요일`, 그 아래 제목·본문)가 쌓입니다.
  노트 카드 시트는 **「제목」이 맨 위(19px 굵게) · 한 칸 띄워 「제목 색」** 순서입니다.
- **v40 사진첩**은 크게 보기가 **사진만 보이는 풀스크린**(위아래 글씨·버튼 없음, **옆으로 밀어 넘기기**, 한 번 탭하거나 아래로 쓸어내리면 닫힘)이고,
  날짜 모아보기 머리에는 **`‹` 뒤로가기**(날짜·태그 왼쪽)와 **수정(연필) 아이콘**이 있습니다. 수정 아이콘을 누르면 **그날 사진 편집 시트**가 열려
  **날짜·태그 수정, `≡` 로 사진 순서 바꾸기, 사진 빼기, `+ 추가`** 를 한 화면에서 하고 저장해요(캡션 칸은 없앴습니다).
  모아보기에는 **사진마다 댓글·대댓글**(동그라미 프사 + 이름 + 내용 + 시각, `답글`·`삭제`)이 사진 아래에 붙고,
  댓글은 `photos.memo` 에 `twolog:c:` 표시로 실려 두 폰이 실시간으로 같은 댓글을 봅니다(예전 글 메모는 그대로 보존).
  사진첩 목록은 **3장을 넘기면 마지막 사진 오른쪽 아래에 작은 `+N`** 배지만(날짜 줄 표기는 없앰), **사진 아래 캡션 줄도 없앴습니다**.
  사진 추가 시트의 **태그 칸은 늘 비어서 시작**하고(한 시트에서 `+ 추가`로 더 담을 때만 유지), 고른 사진 줄 맨 앞 **`≡`** 로 담는 순서를 바꾸면 그 순서대로 저장돼요.
  **사진 달력**은 머리줄(검색·달력·+)이 **위에 붙어 있어** 달력 아이콘을 한 번 더 누르면 목록으로 돌아오고, 요일 줄은 그 머리줄 바로 아래에 붙습니다.
- **v50 부터**는 **모눈 다이어리 도구 줄을 «두 줄»로 되돌리고 · 사진과 글씨를 바로 밑·옆에 놓기**입니다.
  v49 에서 `‹` 뒤로와 한 줄로 합쳤더니 **펜·글씨 도구 판이 날짜(`11.23 MON`)를 가려서**, 위 줄(`‹` 뒤로 하나)과
  **도구 줄(`↶ ↷` 왼쪽 · 펜·`T`·사진 오른쪽)** 을 **다시 «두 줄»** 로 나눴습니다. `‹` 화살표 28px·획 2.2 와 도구 판·글·사진의
  머리 높이(**108px**)는 그대로이고, **도구 판이 열려 있으면 날짜가 그 «아래»로 내려가** 가려지지 않습니다(판을 닫으면 제자리).
  **사진과 글씨를 같이 쓸 때** 사진 바로 밑·옆에 글씨를 놓기 어렵던 문제를 고쳤습니다 —
  사진(을 고른 상태)에서 **사진 바로 아래 빈 종이를 톡 누르면 그 자리에 글 상자**가 생기고(예전엔 고르기만 풀렸어요),
  **사진을 고른 채 `T`를 누르면 그 사진 바로 밑(14px, 같은 자리)** 에 새 글 상자가 놓입니다.
  글 상자는 **사진보다 위(z)** 라 사진에 가려지지 않고, **오른쪽으로 옮겨도 종이 밖으로 나가 잘리지 않게 폭이 자리에 맞춰 줄어듭니다**
  (사진도 폭만큼만 오른쪽으로 갈 수 있어요). 사진 크기 손잡이가 사진 아래를 조금 덜 가리도록 손잡이를 7px 만 내밀게 했습니다.
- **v49 부터**는 **모눈 다이어리 위 줄 정리 · 그리기 좌표 · 지출 화면 제목 · 사진 담기 속도**입니다.
  모눈 다이어리의 **도구 줄(`↶ ↷  펜 T 사진`)이 `‹` 뒤로와 «같은 줄»로 한 단계 위로** 올라가 위 줄이 하나가 됐고(아이폰 375~393px 에서도 줄바꿈 없이),
  **도구 판(펜 도크·글씨 도구)은 그 바로 아래(예전 108 → 56px)**, 글·날짜도 그 높이부터 시작합니다. **`‹` 뒤로 화살표는 22 → 28px**(획 2.2)로 키웠습니다.
  *(v50 에서 두 줄 구조로 되돌렸어요 — 위 v50 항목을 봐 주세요.)*
  **그리는 도중 선이 손가락보다 머리 높이만큼 위에 그려지던 문제**를 고쳤습니다(실시간 선에도 `d41Top()` 을 더함).
  **지출·정산 화면**은 `‹ 11월 ›` 위에 카테고리 이름이 한 번 더 보이던 **제목 줄을 없앴습니다**(내 카테고리·기본 카테고리 둘 다).
  **사진 담기가 훨씬 빨라졌습니다** — 3장씩 **나란히** 압축·업로드하고(예전엔 한 장씩), 압축은 **1200px·품질 0.78**, 올린 뒤 **서명 URL 왕복 없이** 바로 보여 주며,
  업로드가 한 번 실패하면 **한 번 더 시도**합니다. 저장(`save`)은 장마다가 아니라 **1장이 담겼을 때 + 다 끝났을 때 두 번만** 해서 3장 이상도 고른 순서 그대로 끝까지 담깁니다.
- **v47 부터**는 **모눈 다이어리 손보기 + 노트 카테고리 `+` 시트 정리**입니다.
  **되돌리기 `↶` · 다시 실행 `↷`** 단추를 34 → **44px**, 그림을 19 → **27px**(획도 조금 굵게) 로 키워 펜·`T`·사진보다 또렷하게 했습니다.
  **글씨 상자를 끌 때** 아이폰이 손가락을 스크롤·글자 고르기에 채 가서 뚝뚝 끊기거나 아예 멈추던 문제를 고쳤습니다 —
  상자에 `touch-action:none` 으로 터치를 붙잡고(`setPointerCapture`), **4px만 움직여도 곧바로 손가락을 따라가며**(예전 6px),
  화면에서는 `transform`+`requestAnimationFrame` 으로만 옮겨 **끄는 동안 다시 그리지 않고 저장도 하지 않습니다**(손을 뗄 때 한 번만 저장·동기화). 빈 상자(«글을 써 보세요»)도 그대로 끌 수 있어요.
  **색상 스펙트럼 판**은 아이폰과 같은 방향으로 바꿨습니다 — **세로가 색(hue: 빨강→노랑→초록→하늘→파랑→자홍→빨강), 가로가 하양→순색→검정**.
  **프리셋 9색**은 «날씨의 요정» 팔레트(`#F46B62 #DC4A98 #9268C9 #4E8EC1 #4FA78E #F7CE46 #F69B42 #8D6F61`) + 검정입니다.
  모눈 다이어리를 다시 열면 **도구 줄·도구 판 없이 모눈종이가 화면을 꽉 채우고**(보기), **종이를 톡 누르면** 도구 줄이 부드럽게 내려오며 고치기로 바뀝니다(그 탭으로 빈 상자가 생기지 않아요).
  노트 카테고리 `+` 시트에서 **이름을 적고 `추가`를 누르면 방금 만든 줄이 골라지고 그 줄의 «속지» 판이 화면 안으로 따라와** 바로 고를 수 있으며(예전엔 다른 줄에 붙어 있었어요),
  **`저장하기`를 누르면 그 새 카테고리 탭으로 바로 넘어갑니다**.
- **v46 부터**는 **모눈 다이어리의 도구 줄 순서와 색 고르기**입니다. 위 도구 줄은 **↶ 되돌리기 · ↷ 다시 실행이 맨 왼쪽**,
  **펜 · `T` · 사진은 오른쪽**으로 자리를 바꿨습니다(예전엔 반대였어요).
  펜 도크·글씨 도구의 **색 동그라미를 누르면 «색상 스펙트럼 판»** 이 아래에서 올라옵니다 — 아이폰 메모 `색상 › 스펙트럼` 과 같은 모양으로,
  가로가 색 · 세로가 밝기인 캔버스를 **톡 누르거나 손가락으로 끌면** 그 자리 색이 바로 칠해지고 옆에 `#색` 코드가 따라옵니다.
  판 아래에는 **프리셋 9색**과 오른쪽 위 **`×`** 닫기가 있고, 펜 색 동그라미는 22px 로 작게 맞췄어요.
  **글씨 크기 숫자는 회색 작은 글씨에서 검정·굵은 17px** 로 키웠습니다.
- **v44 부터**는 **동기화 오류로 화면이 지워지는 것 막기 + 모눈 다이어리 손대기**입니다.
  서버 표(events·notes·photos·settings)를 읽다가 **하나라도 실패하면(아이폰의 순간 네트워크 끊김) 빈 결과로 화면을 덮어쓰지 않고** —
  지금 화면과 서버 앞면을 그대로 두고 다시 시도하고, 켤 때 실패하면 폰에 저장해 둔 캐시로 열어요. (속지 추가 중 화면 전체가 텅 비던 버그)
  **모눈 다이어리**는 **아이폰 메모장처럼 «보기(스크롤)»로 열리고 종이를 톡 누르면 «고치기»**로 바뉼니다(새 다이어리는 바로 고치기).
  **아이콘바(펜·글씨·사진)는 아래에서 위로** 올라갔고, **«저장» 단추는 없앴어요 — 쓰고 나가면(‹) 자동 저장**됩니다(빈 다이어리는 남지 않아요).

- **v27 부터**는 노트의 **카드 묶음(그룹)까지 함께 동기화**됩니다. 카드의 id·제목·제목색과 항목별 소속(`gid`)을
  `notes.payload.gid` · `settings[groups]` 행으로 저장해, 어느 폰에서 열어도 메모 2개·버킷 3개처럼 나눠 둔 카드가 그대로 보입니다.
  v26 에서 카드 정보 없이 올라가 버린 기기는 **폰에 남은 원본으로 한 번 자동 복구**합니다(플래그 `twolog.groupsRepaired.<coupleId>`).
  같은 버전에서 상대 변경은 토스트 없이 조용히 반영되고, 앱으로 돌아오면(`focus`/`visibilitychange`) 최신 상태를 한 번 당겨옵니다.

## 5. 두 대 실시간 동기화 (Supabase 무료 플랜)

### 5-1. 프로젝트 만들기
1. <https://supabase.com> 가입 → **New project** (리전: `Northeast Asia (Seoul)` 추천)
2. Database 비밀번호는 따로 적어 두세요(이 앱에서는 쓰지 않지만 복구용).

### 5-2. 스키마 넣기
1. 왼쪽 **SQL Editor → New query**
2. 이 폴더의 **`supabase-schema.sql` 전체**를 붙여 넣고 **Run**
3. 만들어지는 것
   - 테이블 5개: `couples`(우리 커플 한 줄) · `events`(일정) · `notes`(할일/버킷/영화·먹방/리스트) · `photos`(사진 정보) · `settings`(테마)
   - RLS: **커플 구성원만** 자기 데이터 읽기/쓰기 (`is_couple_member`)
   - 함수: `join_couple_by_code(code)` · `leave_couple()`
   - Storage: **비공개** 버킷 `photos` (경로 `<couple_id>/<photo_id>.jpg`, 구성원만 접근)
   - Realtime 발행 설정(`events`/`notes`/`photos`/`settings`/`couples`)

### 5-3. 로그인 방식
- **Authentication → Providers → Email** 이 켜져 있는지 확인.
- 두 사람이 바로 쓰려면 **Authentication → Sign In / Providers → Email → "Confirm email" 을 끄는 것**이 가장 간단합니다.
  (켜 두면 가입 후 메일의 확인 링크를 먼저 눌러야 로그인됩니다.)

### 5-4. 주소와 키 넣기
**v25 에서 이미 채워 두었습니다** — `sync.js` 맨 위가 아래처럼 되어 있습니다(이 프로젝트 값).
다른 프로젝트로 옮길 때만 Supabase → **Project Settings → API** 에서 두 값을 다시 복사해 바꿉니다.

```js
var CONFIG = {
  supabaseUrl: "https://qvhupdivtfzhzymovtyy.supabase.co",
  supabaseAnonKey: "sb_publishable_...",   // publishable(anon) 키 — 공개되어도 되고 RLS 가 지킵니다
  ...
};
```

- 두 값을 **비우면** 예전처럼 local 모드(이 기기에만 저장)로 돌아갑니다.
- 화면 확인용으로 잠깐 모드를 바꿀 때는 주소에 `?sync=local` 또는 `?sync=remote` 를 붙입니다.

> `service_role`(secret) 키는 절대 넣지 마세요. anon 키는 RLS 로 보호되므로 앱에 넣어도 됩니다.

### 5-5. 두 사람 연결하기
1. **A 폰**: 앱 열기 → 로그인 화면 → **처음이에요 · 계정 만들기** → 이메일/비밀번호 → 계정 생성
2. **A 폰 설정** → **내 초대 코드** 6자리 확인(예: `418 302`) → 상대에게 알려주기
3. **B 폰**: 같은 주소 열기 → 계정 만들기 → **설정 → 상대 초대 코드**에 A 의 6자리 입력 → **연결**
4. 끝. 이제 A 에서 일정을 추가하면 B 에 몇 초 안에 나타나고, 그 반대도 같습니다.

- B 폰에서는 이름·색의 "나/상대"가 자동으로 뒤집혀 보입니다(A 의 상대 = B 의 나).
- 연결을 끊으려면 **설정 → 커플 연결 해제**. 쌓인 기록은 남습니다.

## 6. 무엇이 저장되고 어디에 저장되나

| 데이터 | 로컬 모드 | 동기화 모드 |
|---|---|---|
| 커플·일정·노트·설정 | `localStorage["twolog:v1:state"]` | Supabase 테이블 5개 |
| 프로필 사진 | `localStorage["twolog:v1:state"]` 의 `couple.pics` | `settings` 행 `avatar:0`(만든 사람) · `avatar:1`(초대받은 사람) |
| 사진 원본 | **IndexedDB**(`twolog` DB, `photos` 스토어) | Supabase Storage `photos`(비공개) |
| 사진 보기 주소 | `URL.createObjectURL(blob)` | 6일짜리 **서명 URL** 을 열 때마다 재발급 |
| 보고 있던 탭·달력 위치 | `localStorage["twolog:v1:ui"]` (기기별, 동기화 안 함) | 같음 |
| 예전 기록 이전 여부 | — | `localStorage["twolog.migrated.<coupleId>"]` (기기별) |
| 노트 카드 묶음 | 상태의 `groups` (같은 `twolog:v1:state`) | `settings` 행 `groups` = `{todo,bucket,log}` 배열 (카드의 모든 필드) |
| 노트 항목의 카드 소속 | 각 항목의 `gid` | `notes.payload.gid` |
| 카드 복구 여부(v27) | — | `localStorage["twolog.groupsRepaired.<coupleId>"]` (기기별) |

- 프로필 사진은 256px 정사각 JPEG data URL(수십 KB)이라 `settings` 의 JSONB 한 칸에 그대로 들어갑니다. 사람마다 **행을 따로** 두어
  두 사람이 동시에 바꿔도 서로 덮어쓰지 않습니다. 상대가 바꾸면 Realtime 으로 몇 초 안에 이 폰에도 나타납니다.
- **로컬 기록 이전(v26)** 은 `localStorage` 를 읽기만 합니다. 사진 원본은 IndexedDB 에서 꺼내 Storage 로 올리고,
  이미 있는 기록은 같은 내용(날짜·제목 등)을 건너뛰므로 버튼을 두 번 눌러도 겹치지 않습니다.

- 사진은 넣기 전에 **긴 변 1200px · JPEG 0.78** 로 줄여 저장합니다(v49 — 예전 1800px·0.82, 요즘 폰 사진 4MB → 대략 100~200KB).
- 저장은 150ms 모아서 하고, 앱이 가려지거나 닫힐 때(`pagehide`/`visibilitychange`) 바로 밀어 넣습니다.
- 오프라인에서 고친 내용도 다음 저장 때 다시 시도하고, 다시 연결되면 `online` 이벤트에서 재전송합니다.
- 상대 기기의 변경은 Realtime 구독(`events`·`notes`·`photos`·`settings`·`couples`)으로 받아 450ms 디바운스 후 다시 읽어 화면에 반영합니다.
  반영할 때는 **토스트를 띄우지 않고** 바뀐 화면만 조용히 다시 그립니다(v27).
- 앱이 다시 앞으로 나오면(`focus`·`visibilitychange`·`pageshow`·`online`) 서버 상태를 한 번 당겨옵니다(v27) — 홈 화면 앱이 쉬는 동안 Realtime 이 끊겨도 최신으로 맞습니다.
- `couples` 행(이름·만난 날·색)도 다시 읽어 오므로, 한쪽에서 바꾼 커플 정보가 상대 화면에 바로 반영됩니다(v27).

## 7. 코드 둘러보기 (sync.js)

`app.js` 는 데이터를 직접 만지지 않고 `TwoLog.createStore()` 가 준 store 만 씁니다.

```js
store.load()                  // 저장된 상태(+이 기기의 ui) 돌려주기
store.persist(S)              // 저장(디바운스) — 화면에서는 이 한 줄
store.flush()                 // 즉시 저장/전송
store.onRemote(doc => ...)    // 상대 기기 변경 수신
store.photos.add(file, meta)  // 압축 → IndexedDB 또는 Storage 업로드
store.photos.urls(photos)     // photo id → 볼 수 있는 주소
store.photos.remove(photo)    // 파일 삭제
store.auth.signIn/signUp/signOut
store.couple.myCode() / join(code) / leave()
store.avatar.set("me", dataUrl)     // v26: 내 프로필 사진을 서버(settings)로
store.local.summary()               // v26: 이 폰에 남은 예전 기록 요약
store.migrate.run({force:true})     // v26: 예전 기록 이어 오기 (자동 이전은 force 없이)
store.repairGroups()                // v27: v26 에서 카드 정보 없이 올라간 노트를 폰 원본으로 1회 복구
store.groupsRepaired()             // v27: 이 기기에서 복구했는지(플래그)
store.pull()                       // v27: 지금 서버 상태를 바로 당겨오기 (깨어날 때 자동)
```

- 로컬 모드: `LocalBackend` (localStorage + IndexedDB).
- 동기화 모드: `SupabaseBackend` — 상태를 테이블 행으로 바꿔 **바뀐 행만** upsert/delete 하고,
  Realtime 을 구독합니다. supabase-js 는 필요할 때만 CDN 에서 ESM 으로 불러옵니다(빌드 불필요).
- 테이블 컬럼 설명은 `supabase-schema.sql` 주석에, 매핑 코드는 `stateToRows` / `rowsToState` 에 있습니다.

## 8. 알려진 한계 / 다음에 붙이면 좋은 것

- **두 사람 전용**입니다. `couples` 는 최대 2명(`members` 배열), 코드도 1회 연결용입니다.
- 푸시 알림이 없습니다. 알림이 필요하면 Web Push(서비스 워커 + VAPID)를 붙이면 됩니다.
- 가계부(지출) 화면은 이번 버전에서 뺐습니다. 데이터 구조(`expenses`)와 카테고리 색은 `app.js` 에 남겨 두어 화면만 다시 붙이면 됩니다.
- iOS 는 오래 안 쓰는 사이트의 저장소를 정리할 수 있습니다. 기록이 중요하면 동기화 모드를 권합니다.
- 사진 원본 화질이 필요하면 `sync.js` 의 `photoMaxDim` / `photoQuality` 를 올리세요(용량·전송 시간 증가).

## 9. 문제가 생기면

| 증상 | 확인 |
|---|---|
| 홈 화면에 추가했는데 주소창이 보임 | `manifest.json` 의 `display` 가 `standalone` 인지, 배포 주소가 https 인지 |
| 서비스 워커가 등록되지 않음 | `https` 또는 `localhost` 인지 (`http://아이피:8080` 은 등록 안 됨) |
| 로그인 후 "로그인이 필요해요" 만 보임 | Supabase Email Provider 켜짐 여부, Confirm email 설정, `CONFIG` 값 오타 |
| 동기화가 「오프라인 · 다시 연결하는 중」 | 5-2 의 스키마 SQL 을 아직 실행하지 않았을 수 있습니다(`public.couples` 없음). 앱은 멈추지 않고 이 기기 기록으로 계속 열립니다. SQL 실행 뒤 앱을 다시 열면 붙습니다. |
| 두 폰이 안 맞춰짐 | 두 사람이 **같은 커플**인지(설정 → 연결됨), Realtime 발행에 5개 테이블이 들어갔는지 |
| 사진이 안 보임 | Storage 버킷 `photos` 가 **비공개**이고 정책 4개가 생성됐는지, 서명 URL 만료(6일) 후 자동 갱신 |
| 예전 프로토타입 데이터가 보임 | `localStorage["couple-app-v1"]` 을 한 번 읽어 `twolog:v1:state` 로 옮깁니다(자동) |

## 10. 디자인 규칙 (깨지지 않게)

- 배경 **#FFFFFF** / 다크 **#111111**, 모서리 **전부 0px** (`border-radius:0` 강제 규칙이 CSS 끝에 있음)
  - 예외: 두 사람의 **프로필 사진 아바타는 동그라미** (`border-radius:50%`)
- **페이지 캡션 색** — 페이지마다 제목 줄 바탕색을 고를 수 있고, 글씨는 라이트·다크 모두 **#111111** 고정
- **화면 모드·컬러·폰트는 「이 폰에만」(v35)** — 라이트/다크 · 페이지 캡션 색 · 홈 제목 색 · 일정 색(소영·준영·공동) · 폰트는
  `localStorage["twolog:v1:localTheme"]` 에만 저장하고 서버(settings `theme`)·`couples` 색으로는 올리지 않습니다.
  그래서 한쪽 폰에서 다크로 바꾸거나 색·폰트를 바꿔도 상대 폰 화면은 그대로예요.
  (일정·노트·사진·디데이·닉네임·프로필 사진은 예전처럼 함께 동기화됩니다. 예전에 서버에 올라간 `theme` 행은
  기기 테마가 아직 없는 폰이 **한 번만** 이어받는 용도로 남겨 둡니다)
- 강조색 코랄 `#D96B52`, 세이지 `#5F6F65`, 기본 일정색 소영 `#F7C6D4` · 상대 `#BCE0F7` · 공동 `#D6C5F7`
- 사진 캡션 글씨는 어떤 배경색을 골라도 **#111111** 고정
- 확인·기본 버튼(`완료`·`저장하기`·`추가하기` … `.btn-primary`)의 글씨는 컬러가 칠해져도 **검정 #111111** (검정에 가까운 아주 어두운 색만 흰 글씨)
- 홈에는 사진첩 미리보기를 두지 않습니다(사진은 사진첩 탭에서만)
